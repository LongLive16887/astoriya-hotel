# Astoria Boutique & SPA — сайт отеля

Сайт бутик-отеля в Самарканде с онлайн-заявками на бронирование, собственным сервером и админ-панелью для управления контентом.

![Превью сайта](public/og-image.jpg)

## Возможности

**Сайт** (узбекский, русский, английский — язык выбирается по браузеру, переключатель в шапке):

- главная: первый экран с выбором дат, об отеле, номера с ценами и фото, SPA и услуги, галерея с фильтрами и просмотром на весь экран, отзывы, новости, контакты с картой;
- страница каждого номера (`/rooms/<id>`), новости (`/news`, `/news/<id>`);
- форма заявки на бронирование с проверкой полей и расчётом стоимости; если заявка не ушла, гость может написать в Telegram или позвонить;
- мобильная версия с панелью «Позвонить / Написать / Забронировать»;
- SEO: мета-теги, Open Graph-превью, разметка schema.org `Hotel`.

**Админ-панель** (`/admin`):

- заявки в реальном времени: статусы (новая → подтверждена → завершена / отменена), заметки персонала, звонок / Telegram / WhatsApp гостю в один клик, экспорт в Excel (CSV), уведомления о новых заявках;
- редактирование номеров и цен, услуг, галереи, отзывов, новостей, контактов и текстов главной страницы — на трёх языках;
- загрузка фото с автоматическим сжатием (WebP, до 2000 px) на сервер; библиотека загруженных фото;
- администраторы: добавление, удаление, новый пароль тому, кто забыл свой, смена своего пароля;
- предупреждение о несохранённых изменениях; правки двух администраторов одновременно не затирают друг друга.

## Как устроено

```
Браузер ──HTTPS──> Caddy ─┬─ /            сайт (файлы из dist/)
                          ├─ /uploads/*   загруженные фото
                          └─ /api/*  ───> Node.js-сервер (Hono) ──> SQLite
```

- **Сайт** — React 18, TypeScript, Vite 7, React Router 7, i18next, lucide-react. Шрифты подключены локально.
- **Сервер** (`server/`) — Node.js 24, [Hono](https://hono.dev), база SQLite (встроенный модуль `node:sqlite`, один файл). Вход по email и паролю (scrypt), сессия в защищённой cookie, ограничение числа попыток входа и заявок с одного адреса. Изменения приходят в админ-панель мгновенно (Server-Sent Events).
- **Caddy** выдаёт и продлевает сертификат HTTPS сам и отдаёт статические файлы.
- **Автодеплой**: коммит в `main` проверяется и собирается в GitHub Actions, сервер сам ставит новую сборку в течение минуты.

Для разработки нужен **Node.js 22.13+** (на сервере стоит 24).

## Быстрый старт

```bash
npm install
npm run dev                                   # сайт http://localhost:3000 и API (база в ./data)
npm run admin -- admin:add you@example.com    # администратор; пароль появится в консоли
```

При первом запуске база заполняется текстами и фото по умолчанию (`src/content/defaults.ts`) и примерами новостей — дальше всё редактируется в админ-панели.

## Сервер и деплой

Сервер: `13.140.177.106` (Ubuntu/Debian). Настройки, которые не являются секретом, лежат в `deploy/config.env`.

### Первая настройка

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**, имя `SERVER_SSH_PASSWORD`, значение — пароль root сервера.
2. У регистратора домена: A-запись домена (и `www`) → `13.140.177.106`.
3. В `deploy/config.env` впишите домен в `DOMAIN=` и сделайте коммит — запустится workflow **Server setup** (его можно запустить и вручную во вкладке Actions).

Workflow подключается к серверу по SSH и выполняет `deploy/server/setup.sh`: ставит Node.js, Caddy, создаёт пользователя `astoria`, службы systemd, ежедневные резервные копии, агент автодеплоя и текущую сборку сайта. Скрипт можно запускать повторно — например, после смены домена.

Первый администратор (`ADMIN_EMAIL` из `deploy/config.env`) создаётся при первой настройке. Лог Actions публичный, поэтому его пароль выводится там только в зашифрованном виде (ключом `deploy/server/bootstrap.pub`). После входа смените пароль и добавьте свой email в разделе «Администраторы».

После настройки секрет `SERVER_SSH_PASSWORD` для обновлений сайта не нужен: его можно удалить и сменить пароль root.

### Обновление сайта (CI/CD)

`.github/workflows/ci.yml`:

1. На каждый pull request и коммит в `main`: ESLint, тесты, сборка сайта и сервера.
2. Для коммита в `main` сборка публикуется в релиз GitHub `production`.
3. На сервере таймер `astoria-deploy.timer` раз в минуту проверяет этот релиз и ставит новую сборку: сверяет контрольную сумму, делает резервную копию базы, перезапускает сервер и проверяет `/api/health`. Если новая версия не запустилась, сервер сам возвращается к предыдущей.
4. Последний шаг workflow ждёт, пока сайт не сообщит, что работает на новом коммите.

### На сервере

| Что | Где |
| --- | --- |
| база, загруженные фото, резервные копии | `/var/lib/astoria/` (`astoria.db`, `uploads/`, `backups/`) |
| сборки сайта | `/opt/astoria/releases/<коммит>`, текущая — `/opt/astoria/current` |
| настройки сервера | `/etc/astoria/astoria.env` |
| Caddy | `/etc/caddy/Caddyfile` (создаётся из `deploy/server/Caddyfile`) |

Полезные команды (от root):

```bash
journalctl -u astoria -f                 # журнал сервера
journalctl -u astoria-deploy             # журнал автодеплоя
systemctl restart astoria                # перезапуск
astoria() { runuser -u astoria -- env $(xargs < /etc/astoria/astoria.env) node /opt/astoria/current/server/index.mjs "$@"; }
astoria admin:list                       # администраторы
astoria admin:password you@example.com   # новый пароль (напечатает его)
astoria backup                           # резервная копия базы сейчас
```

Резервная копия базы делается каждую ночь в 03:30 и перед каждым обновлением; хранятся последние 14. Копии лежат на том же сервере — периодически скачивайте `/var/lib/astoria/backups` и `/var/lib/astoria/uploads` к себе.

Вернуться к предыдущей сборке вручную: `ln -sfn releases/<коммит> /opt/astoria/current && systemctl restart astoria`.

### Что где хранится

| Таблица | Содержимое |
| --- | --- |
| `content` | настройки сайта и списки: номера, услуги, галерея, отзывы (JSON, с номером версии) |
| `posts` | новости, включая черновики |
| `bookings` | заявки гостей, статусы и заметки |
| `admins`, `sessions` | администраторы (пароли — только в виде хэша scrypt) и их входы |

## Работа в админ-панели

- **Обзор** — новые заявки, ближайшие заезды, быстрые действия. Кнопка «Уведомлять о новых заявках» включает уведомления браузера на компьютере (пока вкладка открыта); на телефоне о новой заявке сообщит сообщение внутри панели. Число новых заявок видно и в заголовке вкладки.
- **Заявки** — вкладки по статусам, поиск по имени и телефону. В карточке заявки: связаться с гостем, сменить статус, оставить заметку, удалить.
- **Номера и цены** — порядок на сайте, показ/скрытие, копия номера. В редакторе: тексты, цены в сумах и долларах, вместимость, удобства, фото (первое — обложка).
- **Услуги и Отзывы** — добавление, редактирование, порядок, скрытие.
- **Галерея** — загрузка фото, подписи, категории, порядок.
- **Новости** — публикация и редактирование; черновики на сайте не видны. Новости идут по дате, новые — первыми.
- **Настройки сайта** — контакты, карта, время заезда и выезда, тексты и фото главного экрана, блоков «Об отеле» и SPA.
- **Администраторы** — кто может входить в панель. Забытый пароль заменяет другой администратор (значок ключа); если администратор один — команда `admin:password` на сервере.

Переключатель **UZ / RU / EN** рядом с каждым текстовым полем меняет язык для всей формы. Точкой отмечены незаполненные языки — там сайт покажет текст на другом языке.

Изменения видны гостям сразу после сохранения (у тех, кто уже открывал сайт, — при следующем открытии страницы).

## Разработка

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сайт и API для разработки (`dev:web` и `dev:api` — по отдельности) |
| `npm run admin -- <команда>` | команды сервера: `admin:add`, `admin:password`, `admin:list`, `backup` |
| `npm run build` | проверка типов, сборка сайта в `dist/` и сервера в `build/server/` |
| `npm run preview` | собранный сервер, который отдаёт и сайт: http://localhost:3001 |
| `npm run lint` | ESLint |
| `npm test` | тесты (Vitest): сайт, админ-панель и API |
| `npm run package` | архив сборки для сервера в `release/` |

### Структура

```
src/
├── content/      типы данных, контент по умолчанию, загрузка и нормализация контента
├── i18n/         тексты интерфейса сайта (uz, ru, en)
├── lib/          запросы к API, форматирование дат и цен, ссылки, проверка заявки
├── components/   общие компоненты (логотип, диалог, лайтбокс…)
├── site/         публичный сайт: шапка и подвал, секции главной, страницы, форма бронирования
└── admin/        админ-панель: вход, разделы, редакторы, живые обновления, загрузка фото
server/           API: база, вход, контент, новости, заявки, фото, команды администрирования
deploy/           настройки сервера, скрипт установки, агент автодеплоя, службы, Caddy
.github/workflows CI/CD и настройка сервера
public/images/    фотографии отеля (WebP)
```

Фотографии по умолчанию лежат в `public/images`. Чтобы заменить их без админ-панели, положите новые файлы туда (лучше в WebP, до 2000 px по длинной стороне) и поправьте пути в `src/content/defaults.ts`.
