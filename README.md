# Astoria Boutique & SPA — сайт отеля

Сайт бутик-отеля в Самарканде с онлайн-заявками на бронирование и админ-панелью для управления контентом.

![Превью сайта](public/og-image.jpg)

## Возможности

**Сайт** (узбекский, русский, английский — язык выбирается по браузеру, переключатель в шапке):

- главная: первый экран с выбором дат, об отеле, номера с ценами и фото, SPA и услуги, галерея с фильтрами и просмотром на весь экран, отзывы, новости, контакты с картой;
- страница каждого номера (`/rooms/<id>`), новости (`/news`, `/news/<id>`);
- форма заявки на бронирование с проверкой полей и расчётом стоимости; если онлайн-заявки недоступны, гость может отправить заявку в Telegram;
- мобильная версия с панелью «Позвонить / Написать / Забронировать»;
- SEO: мета-теги, Open Graph-превью, разметка schema.org `Hotel`.

**Админ-панель** (`/admin`):

- заявки в реальном времени: статусы (новая → подтверждена → завершена / отменена), заметки персонала, звонок / Telegram / WhatsApp гостю в один клик, экспорт в Excel (CSV), уведомления браузера о новых заявках;
- редактирование номеров и цен, услуг, галереи, отзывов, новостей, контактов и текстов главной страницы — на трёх языках;
- загрузка фото с автоматическим сжатием (WebP, до 2000 px) и библиотека уже загруженных фото;
- предупреждение о несохранённых изменениях.

## Технологии

React 18, TypeScript, Vite 7, React Router 7, i18next, Firebase (Firestore, Authentication, Storage), lucide-react. Шрифты Cormorant Garamond и Manrope подключены локально (без Google Fonts).

Для работы нужен **Node.js 20.19+ или 22.12+**.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:3000
```

Без настроек Firebase сайт полностью работает на встроенном контенте (`src/content/defaults.ts`), но заявки не сохраняются (гостю предлагается написать в Telegram), а админ-панель показывает инструкцию по подключению.

## Firebase и админ-панель

Все данные сайта и заявки хранятся в Firebase. Бесплатного тарифа Spark хватает для сайта, заявок и админ-панели; для загрузки фото см. шаг 7.

1. **Создайте проект** в [Firebase Console](https://console.firebase.google.com) → «Add project».
2. **Веб-приложение.** Project settings → General → Your apps → значок `</>`. Скопируйте значения из `firebaseConfig` в файл `.env` (образец — `.env.example`) или в переменные окружения хостинга:
   ```
   VITE_FIREBASE_API_KEY=…
   VITE_FIREBASE_AUTH_DOMAIN=…
   VITE_FIREBASE_PROJECT_ID=…
   VITE_FIREBASE_STORAGE_BUCKET=…
   VITE_FIREBASE_MESSAGING_SENDER_ID=…
   VITE_FIREBASE_APP_ID=…
   VITE_SITE_URL=https://ваш-домен
   ```
   Эти ключи не секретные — доступ к данным защищают правила безопасности (шаг 4).
3. **Вход по паролю.** Authentication → Sign-in method → Email/Password → Enable.
4. **База данных.** Firestore Database → Create database → режим *production*. Регион выберите в Европе (например, `europe-west3`, Франкфурт) — для гостей из Узбекистана это быстрее региона США по умолчанию; поменять его потом нельзя. Затем загрузите правила и индексы из репозитория:
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase use --add            # выберите свой проект
   firebase deploy --only firestore
   ```
5. **Администратор.** Authentication → Users → «Add user» (email и пароль). Скопируйте его **User UID**. Firestore Database → «Start collection» `admins` → Document ID = этот UID → поле `email` (string) с адресом. Подсказка: если войти в `/admin` аккаунтом без прав, панель покажет UID и кнопку «Скопировать».
6. **Первый вход.** Откройте `/admin`, войдите и нажмите на главной панели «Сохранить контент» — тексты и фото по умолчанию запишутся в базу, и их можно будет редактировать.
7. **Загрузка фото** (один из вариантов):
   - *Firebase Storage* — Storage → Get started. Для новых проектов Firebase требует тариф **Blaze** (оплата по факту, нужна банковская карта; для фото сайта отеля это обычно центы в месяц или укладывается в бесплатный лимит). Затем `firebase deploy --only storage` — при первом деплое CLI попросит разрешить правилам Storage читать список администраторов из Firestore, ответьте «Yes».
   - *Cloudinary* (бесплатно, без карты) — создайте аккаунт, Settings → Upload → Upload presets → «Add upload preset» с режимом **Unsigned**, и задайте `VITE_CLOUDINARY_CLOUD_NAME` и `VITE_CLOUDINARY_UPLOAD_PRESET`.
   - Без хранилища можно выбирать уже имеющиеся фото и вставлять ссылки на изображения.

Добавить ещё администратора — повторите шаг 5 для нового пользователя. Убрать доступ — удалите его документ из `admins`.

### Что где хранится

| Коллекция / документ | Содержимое | Кто может читать / писать |
| --- | --- | --- |
| `content/settings` | контакты, тексты главной, фото | все читают, пишут админы |
| `content/rooms`, `services`, `gallery`, `reviews` | списки `items` | все читают, пишут админы |
| `posts/<id>` | новости | опубликованные — все, черновики и запись — админы |
| `bookings/<id>` | заявки гостей | гости только создают (с проверкой полей), остальное — админы |
| `admins/<uid>` | список администраторов | создаётся вручную в консоли |

Правила — в `firestore.rules` и `storage.rules`, они покрыты тестами (`npm run test:rules`).

## Публикация сайта

```bash
npm run build      # готовый сайт в папке dist/
```

- **Firebase Hosting:** `firebase deploy --only hosting` (настройки уже в `firebase.json`).
- **Vercel / Netlify:** команда сборки `npm run build`, папка `dist`, переменные окружения из `.env`. Переадресация для страниц уже настроена (`vercel.json`, `public/_redirects`).
- **Любой другой хостинг:** сервер должен отдавать `index.html` для всех адресов, которых нет в `dist` (это одностраничное приложение).

После публикации укажите `VITE_SITE_URL` — тогда превью ссылок в Telegram и соцсетях будут с картинкой.

## Работа в админ-панели

- **Обзор** — новые заявки, ближайшие заезды, быстрые действия. Кнопка «Уведомлять о новых заявках» включает уведомления браузера (пока вкладка открыта); число новых заявок видно и в заголовке вкладки.
- **Заявки** — вкладки по статусам, поиск по имени и телефону. В карточке заявки: связаться с гостем, сменить статус, оставить заметку, удалить.
- **Номера и цены** — порядок на сайте, показ/скрытие, копия номера. В редакторе: тексты, цены в сумах и долларах, вместимость, удобства, фото (первое — обложка).
- **Услуги, Галерея, Отзывы, Новости** — добавление, редактирование, порядок, скрытие. Новости можно сохранить черновиком.
- **Настройки сайта** — контакты, карта, время заезда и выезда, тексты и фото главного экрана, блоков «Об отеле» и SPA.

Переключатель **UZ / RU / EN** рядом с каждым текстовым полем меняет язык для всей формы. Точкой отмечены незаполненные языки — там сайт покажет текст на другом языке.

Изменения видны гостям сразу после сохранения (у тех, кто уже открывал сайт, — при следующем открытии страницы).

## Разработка

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сайт для разработки |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run lint` | ESLint |
| `npm test` | юнит-тесты (Vitest) |
| `npm run emulators` | локальные эмуляторы Firebase (нужны `firebase-tools` и Java 11+) |
| `npm run dev:emulators` | сайт, подключённый к эмуляторам |
| `npm run test:rules` | тесты правил Firestore и Storage на эмуляторах |

Чтобы попробовать админ-панель локально: запустите `npm run emulators` и `npm run dev:emulators`, откройте Emulator UI (http://127.0.0.1:4000), в разделе Authentication добавьте пользователя, а в Firestore — документ `admins/<его UID>`.

### Структура

```
src/
├── content/      типы данных, контент по умолчанию, загрузка и нормализация контента
├── i18n/         тексты интерфейса сайта (uz, ru, en)
├── lib/          Firebase, форматирование дат и цен, ссылки, проверка заявки
├── components/   общие компоненты (логотип, диалог, лайтбокс…)
├── site/         публичный сайт: шапка и подвал, секции главной, страницы, форма бронирования
└── admin/        админ-панель: вход, разделы, редакторы, работа с Firestore и загрузкой фото
public/images/    фотографии отеля (WebP)
tests/rules/      тесты правил безопасности
```

Фотографии по умолчанию лежат в `public/images`. Чтобы заменить их без админ-панели, положите новые файлы туда (лучше в WebP, до 2000 px по длинной стороне) и поправьте пути в `src/content/defaults.ts`.
